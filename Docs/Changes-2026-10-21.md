# 2026-10-21 — Step 1: stability & performance

## Memory (suspected cause of the "killed" / signal 9 exit)
- MetalVideoRenderer: at most 3 frames in flight (DispatchSemaphore). When the GPU or display falls behind, new frames are dropped (counted as Dropped Frames) instead of queueing command buffers that each retain a decoder pixel buffer.
- CVMetalTexture objects (luma/chroma) are now kept alive until the command buffer completes (Apple requirement; previously released right after encoding).
- CVMetalTextureCacheFlush once a second and on memory warning.
- Theater copy texture (up to 4K, ~33 MB) is released when the theater is off.
- `releaseCachedResources()` on memory warning (UIApplication.didReceiveMemoryWarningNotification, logged as `[Memory] warning — footprint N MB`) and when a Remote Play session ends.
- RenderStatistics no longer spawns 2–3 main-actor Tasks per frame; render/decode threads write to a locked accumulator, a 1 Hz timer publishes.

## Stream recovery
- Keyframe requests from failed decodes rate-limited to one per 500 ms (previously every failed frame while waiting for an IDR).
- Stall watchdog: no decoded frame for 1 s → request keyframe (once per second); 8 s → automatic reconnect (max 2 times until the picture flows again). Disabled while the login passcode prompt is up.

## Stats panel (player › Stats)
- New "Remote Play Stream" section: measured bitrate, hardware decode time, frame jitter, frames lost, decode errors, keyframe requests.
- Memory section: app footprint (phys_footprint), video texture MB, memory warning count.
- Blue brand background.
- Not yet: network RTT — needs a new shim call (vp_session_get_stats) and a library rebuild; planned together with the next shim change.

## How to check the memory issue
Run from Xcode, open Stats during a long session (theater + 4K upscale), and watch App Memory. If a `[Memory] warning` line appears before a kill, it was jetsam.
